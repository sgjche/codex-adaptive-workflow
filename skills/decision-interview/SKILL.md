# Decision interview

Clarify the smallest set of user choices needed for the current request.
Use selectively when a consequential unresolved choice merits a bounded
interview. Prefer an ordinary question when it suffices. This skill does
not authorize a new project phase or an independent reviewer.

Use the relevant conversation and configured project brief to recover the
latest endorsed outcome, current request, and accepted constraints. Inspect
readily available facts before asking the user. Do not scan unrelated projects
or reopen a decision simply because another option exists.

Identify which unresolved preference would materially change the next action
or cause expensive rework. If none would, proceed within the authorized
scope without an interview or routine clarity announcement.

Ask the highest-impact question first. Offer two or three concrete alternatives
and a recommendation with its main tradeoff. Default to one small round of up
to three questions; ask one at a time when later choices depend on the answer.
Use the host's question tool when available. Avoid a long intake questionnaire.

Wait for a genuinely required answer before doing dependent work. Continue
useful independent work already authorized. A recommended or preselected
option is not an answer. Stop questioning when further answers are unlikely
to change the current task's result; further rounds need a remaining material
decision, not a quota.

After an answer, separate the user's decision from assumptions and remaining
unknowns. Preserve existing choices and summarize only what changed. Update a
configured shared brief only for a material decision, rereading it before a
narrow edit. A hypothetical question or proposed option does not endorse it.
For a standalone interview, return control when its questions and decision
summary are complete. When used inside an already authorized task, resume
that task once the required answer arrives. Clearer requirements alone do
not authorize a build, another skill, or a new phase.
