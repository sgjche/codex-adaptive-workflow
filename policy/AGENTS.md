## User-guided project alignment

Use `conversation-alignment` for substantive ongoing project work. Read the
selected project's brief (explicit pointer or root `PROJECT_BRIEF.md`) and
follow the current request's scope. Skip unrelated or trivial requests. This
workflow does not authorize Goals, schedules, delegation, or follow-up turns.

## Adaptive task workflow

For substantive work, separate the latest user-endorsed outcome, this request's
scope, working assumptions, and actual evidence. Use the project's existing
brief/checkpoint when relevant; do not create state files for trivial requests.
Later explicit user steering can supersede an earlier goal; a hypothetical
question or proposed option does not endorse a change.

Choose the smallest useful action. A consequential missing user decision calls
for a focused question; a consequential discoverable fact calls for inspection.
Proceed when sufficiently clear or the remaining choice is low-impact and
reversible. Do not reopen settled decisions without new reason.

Select process skills only for a distinct material need: `decision-interview`
for unresolved user choices that merit a bounded interview; `find-unknowns`
for a consequential assumption needing a bounded investigation; and
`evidence-checkpoint` for an important claim with conflicting evidence, a
suspected shortcut, or acceptance-impacting validation changes. Prefer an
ordinary question or check when it suffices. Honor each skill's invocation
policy and task-specific opt-outs. Do not run a fixed skill sequence or
duplicate the domain workflow's validation.

For automatic use of these three skills, send one brief commentary notice:
`Skill: <display name> — <concrete task reason>`.
Announce when starting the procedure, once per distinct invocation; combine
with an existing matching progress notice. Do not repeat for tool calls,
pauses, or resuming that invocation, or announce availability/inspection alone.
Use the existing context; no extra tools or persistent log for the notice.

Reconsider the approach after a material correction, contrary evidence, or
repeated unsuccessful attempts without new information. Preserve accepted
work and update existing recoverable state only for material decisions or
verified changes, distinguishing them from assumptions. Reread before edits.

Beyond those notices, keep checks quiet when aligned. Reuse valid evidence
and disclose material gaps. Optional checks do not authorize expensive
research, a new project phase, a full-transcript audit, Goals, schedules, or
follow-up turns.
Independent reviewer agents remain manual: use them only on an explicit
human request, not merely because a process skill activates. A standalone
interview/review ends with its requested findings; an embedded check may
resume the same authorized task. Complete that request and return control.
